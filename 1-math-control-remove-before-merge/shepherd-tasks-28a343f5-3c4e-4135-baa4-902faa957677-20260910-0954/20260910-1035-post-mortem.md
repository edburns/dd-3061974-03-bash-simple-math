## Section 7: Failure Analysis

The campaign had no terminal failure: the manifest and invocation both report exit code `0`, and both target PRs merged. Two recoverable orchestration command failures occurred.

### 7.1 Phase-1 Check-Name False Negative

During stage 30 for [#3](https://github.com/edburns/dd-3061974-03-bash-simple-math/issues/3), a HEAD-specific check query required a check run named `Test math tool`. GitHub exposed only the workflow/job-level name `Shepherd task math tool`, producing:

```text
SHEPHERD FAILED: pending=0 failing=0 relevant_success=0
```

The local shepherd correctly treated this as an observability mismatch rather than a product failure. It inspected workflow run `34507552874`, verified the successful `Test math tool` job step, and continued. Root cause: the gate assumed a workflow step name would be represented as a commit check-run name.

### 7.2 Phase-2 Malformed `jq` Gate

During stage 40 for [#5](https://github.com/edburns/dd-3061974-03-bash-simple-math/pull/5), the first aggregate status-check filter had an unbalanced expression and exited 3 with:

```text
jq: error: syntax error, unexpected INVALID_CHARACTER
```

The local shepherd repaired the expression using an explicit `if ... then ... else ... end` branch, re-ran the complete atomic gate, and obtained `FINAL_GATES_PASS=true` before merge. Root cause: an inline, deeply nested `jq` predicate was not syntax-validated before execution.

### 7.3 Product Finding

The CCRA finding on [#4](https://github.com/edburns/dd-3061974-03-bash-simple-math/pull/4) was not a campaign failure, but it was a valid cross-platform defect. The initial implementation used a Windows-only PowerShell option despite Linux CI. The repair was surgical, test-backed, and verified by a clean current-head review. No unresolved product defects are visible in the captured logs.

## Section 8: Observations and Recommendations

### 8.1 What Worked Well

- **Serial task discipline:** [#3](https://github.com/edburns/dd-3061974-03-bash-simple-math/issues/3) began only after [#4](https://github.com/edburns/dd-3061974-03-bash-simple-math/pull/4) merged, preserving the planned dependency.
- **Objective acceptance contract:** Both stages used `eng/test-math-tool.ps1` with pinned Pester 5.7.1. The final suite passed 27/27 tests.
- **Current-head review enforcement:** Review IDs and commit SHAs were checked before merge, preventing stale reviews from satisfying the gate.
- **Effective CCRA feedback:** One review comment found a real Linux portability problem that local tests alone had not exposed.
- **Surgical local remediation:** The shepherd changed one unsupported option, retained existing behavior, and verified the repair before push.
- **Control-mode integrity:** Lesson propagation remained off and `campaign-lessons.md` was not modified.
- **Strong convergence:** One PR required a single fix round; the other required none.

### 8.2 What Could Be Improved

- **Normalize GitHub Actions evidence:** The stage-30 gate should support workflow-, job-, and step-level naming explicitly. A successful workflow with a required named step should not first emit `SHEPHERD FAILED`.
- **Move complex `jq` into tested helpers:** Deep inline predicates are hard to audit and produced a transient syntax failure. Store the filter in a reusable script or validate it with fixture JSON before applying the merge gate.
- **Record review metrics structurally:** The markdown logs contain review IDs and comment counts, but no dedicated summary artifact. Each phase should emit a compact result JSON containing PR, reviewed SHA, rounds, comments, repair commits, checks, and merge SHA.
- **Expose non-redacted aggregate token totals:** Current artifacts preserve cache counters but redact input/output totals. A privacy-safe numeric session aggregate would improve cost comparison without exposing prompt content.
- **Avoid ambiguous failure strings in command source:** Searches for failure signatures match guard clauses that never fired. Structured tool exit records or explicit attempt-result summaries would separate latent guards from executed failures.

### 8.3 Recommended Script and Skill Changes

1. Update stage 30 CI validation to query the successful workflow run and required job step when the commit check API exposes only a workflow-level check name.
2. Add fixture-based tests for stage 40's `statusCheckRollup` filter covering `CheckRun` and `StatusContext` entries, allowed conclusions, exempt guard checks, pending checks, and failures.
3. Emit `stage-30-result.json` and `stage-40-result.json` beside each task log with timestamps, review counts, comment counts, test totals, failures recovered, and final SHAs.
4. Add an early cross-platform lint or smoke execution for PowerShell child-process helpers on the same OS as CI. This could have caught `-NoNewWindow` before CCRA.
5. Preserve the current serial ordering, exact-base checks, current-head review checks, and isolated repair worktree behavior; these controls directly supported the 100% completion rate.
